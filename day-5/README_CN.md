# AWS 安全：安全组和 NACL

AWS (Amazon Web Services) 提供多层安全保护来保护其云基础设施中的资源和数据。AWS 网络安全的两个重要组件是安全组和网络访问控制列表 (NACL)。让我们来了解它们各自的工作原理：

    安全组：
        安全组在实例级别充当 Amazon EC2 实例（虚拟服务器）的虚拟防火墙。它们通过允许或拒绝特定协议、端口和 IP 地址来控制入站和出站流量。
        每个 EC2 实例可以关联一个或多个安全组，每个安全组由入站和出站规则组成。
        入站规则确定允许到达 EC2 实例的流量，而出站规则控制离开实例的流量。
        安全组可以使用 IP 地址、CIDR 块、安全组 ID 或 DNS 名称来指定流量的源或目标。
        它们在实例级别运行，在允许流量到达实例之前评估规则。
        安全组是有状态的，这意味着如果入站规则允许流量，相应的出站流量会自动被允许，反之亦然。
        对安全组规则的更改会立即生效。

    网络访问控制列表 (NACL)：
        NACL 是在子网级别运行的额外安全层。它们在子网边界充当入站和出站流量的无状态流量过滤器。
        与安全组不同，NACL 与子网关联，每个子网只能有一个 NACL。但是，多个子网可以共享同一个 NACL。
        NACL 由编号规则列表组成（按升序编号），按从最低到最高的顺序评估。
        NACL 中的每个规则包括规则编号、协议、规则动作（允许或拒绝）、源或目标 IP 地址范围、端口范围和 ICMP（互联网控制消息协议）类型。
        NACL 规则可以配置为根据定义的条件允许或拒绝特定类型的流量。
        它们是无状态的，这意味着如果入站规则允许流量，相应的出站流量必须使用单独的出站规则明确允许。
        对 NACL 规则的更改可能需要一些时间才能传播到使用关联子网的所有资源。
